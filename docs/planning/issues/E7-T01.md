# E7-T01 Start and join a session

Labels: `agent-task`, `epic:collaboration`, `size:L`, `kind:ui`

## Context
Phase 4 relay and ADR-0006. UI spec Collaboration panel. The WebSocket client does not exist in ccmm-app.

## Goal
Start session and Join session open a socket to the relay.

## Scope
Buttons on the Session view. Start creates an invite token the way the server already expects and copies `Invite link copied`. Join asks for the token. Relay URL comes from settings. Display name comes from settings.

## Out of scope
No handshake yet (E7-T02). No carets. No new protocol types. Use join, presence, and chat as they exist.

## Design
Socket work on a daemon thread `ccmm-relay`. Incoming frames are applied with the existing applyRemote batch.
Status copy: `Not sharing`, `Connecting…`, `Could not connect`, `Wrong or expired invite`.
The panel states that `The relay can see the text you share`.
Do not put the token in the log.

## Implementation steps
1. Client wrapper around the existing message codec.
2. Session view buttons.
3. Tests with an in-memory socket, not a public relay.

## Acceptance criteria
- Given a wrong token, when join finishes, then the view reads `Wrong or expired invite` and no remote edit is applied.
- Given a successful join, when presence arrives, then the name is listed.
- Given the idle view, when it renders, then it reads `Not sharing` and `The relay can see the text you share`.

## UX spec
Wireframe: docs/design/wireframes/collaboration.md and docs/design/UI_SPEC.md.
Tokens only. Minimum window 900x600. Hit target at least 24.
Copy: `Not sharing`, `Start session`, `Join session`, `Connecting…`, `Could not connect`, `Wrong or expired invite`, `Invite link copied`, `The relay can see the text you share`, `End session`.
Accessibility: icon-only controls use the tooltip as the accessible name. Ctrl shortcuts are Cmd on macOS.
