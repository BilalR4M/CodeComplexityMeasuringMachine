# E7-T10 Enforce roles and approval

Labels: `agent-task`, `epic:collaboration`, `size:L`, `kind:code`

## Context
COLLABORATION.md roles. ADR-0006 token. Host approval defaults on.

## Goal
Host, editor, and viewer roles are enforced on the relay.

## Scope
Join waits for host approval by default. Host can set a peer to editor or viewer. Viewer text ops are ignored by the server. Viewer may send thread and chat messages. Ask to edit sends a request the host grants or refuses.

## Out of scope
No accounts. No voice.

## Design
Default role on join is viewer until the host promotes, except the host. Document this in the session view: `Waiting for the host` and `You can comment`. A viewer client's local editor is not editable. The server is the authority even if the client is modified.

## Implementation steps
1. Server tests for a dropped op.
2. Approval flow.
3. Read-only editor binding.

## Acceptance criteria
- Given a viewer, when they send an insert, then no other client receives it.
- Given approval required, when a guest connects, then they see `Waiting for the host` and receive no file text.
- Given the host grants editor, when the guest sends an insert, then peers receive it.

## Tests
RoleEnforcementTest on the server. ApprovalClientTest on the app.
