# E1-T02 Add the activity bar

Labels: `agent-task`, `epic:workbench`, `size:M`, `kind:ui`

## Context
UI spec activity list: Explorer, Search, Outline, Collaboration, Settings.

## Goal
An activity bar switches the side-bar view.

## Scope
Five toggle buttons. Explorer shows the existing tree. The other four show their empty state from the UI spec.

## Out of scope
No search index, outline data, session, or settings fields. Those are later issues.

## Design
ActivityBar in the workbench package. Buttons are 48x48, icon 16, accessible names:
Explorer (Ctrl+Shift+E), Search (Ctrl+Shift+F), Outline (Ctrl+Shift+O), Collaboration, Settings (Ctrl+,).
Selecting a button shows that view and collapses nothing else. Ctrl+B hides the side bar and the activity bar stays.
Tokens only. Placeholder views use the empty copy from UI_SPEC.md.

## Implementation steps
1. Add the bar and five views.
2. Wire the shortcuts in code for now; E1-T07 moves them into the keymap.
3. Test selection and the accessible names.

## Acceptance criteria
- Given the activity bar, when Search is clicked, then the side bar shows `Type to search in <folder>` or `No folder opened`.
- Given keyboard focus on Explorer, when the button is read by the accessible text, then it includes Explorer.

## Tests
ActivityBarTest.

## Verification
mvn -B -ntp -pl ccmm-app -am test

## Depends on
E1-T01.

## Blocks
E3-T02's view hosts, E4, E7-T01's panel host.

## Risks and fallbacks
Shortcuts registered twice when E1-T07 lands. E1-T07 deletes the temporary handlers.

## UX spec
Wireframe: docs/design/wireframes/workbench.md and the matching section of docs/design/UI_SPEC.md.
States: populated, disabled when the side bar is hidden.
Visuals: token names from docs/design/TOKENS.md only. Minimum window 900x600. Hit target at least 24.
Copy: Tooltips as in the accessible names above.
Accessibility: every icon-only control has an accessible name equal to its tooltip. Contrast uses the token ratios.
