# E1-T08 Apply theme tokens

Labels: `agent-task`, `epic:workbench`, `size:M`, `kind:ui`

## Context
docs/design/TOKENS.md. ADR-0013. E0-T04's go.

## Goal
The workbench uses the dark token stylesheet by default.

## Scope
Two stylesheets, dark and light, looked-up colours named from the tokens. Default dark. A package-visible switch for tests. Font: system UI font. Editor font waits for the font files from this issue only if ADR-0014 is accepted; otherwise system monospace and a status note.

## Out of scope
No AtlantaFX. No hex in Java sources.

## Design
Stylesheets live in resources/theme/dark.css and light.css. Workbench.applyTheme(Theme.DARK). Pseudo-classes only. If ADR-0014 is not accepted, do not vendor the font; use the platform monospace and leave a code comment pointing at the ADR.

## Implementation steps
1. Write the stylesheets from TOKENS.md.
2. Apply dark at startup.
3. Test that the root style class is theme-dark.

## Acceptance criteria
- Given startup, when the scene is created, then the root has style class theme-dark.
- Given applyTheme(LIGHT), when it runs, then the root has theme-light and not theme-dark.
- No Java source under ccmm-app/src/main contains a hex colour.

## Tests
ThemeTest.

## Verification
mvn -B -ntp -pl ccmm-app -am test

## Depends on
E0-T04 go, and the owner accepting ADR-0013. Font files additionally need ADR-0014.

## Blocks
None.

## Risks and fallbacks
If E0-T04 is a no-go, fix tokens first. Do not add a theme library.

## UX spec
Wireframe: docs/design/wireframes/settings.md and the matching section of docs/design/UI_SPEC.md.
States: populated.
Visuals: token names from docs/design/TOKENS.md only. Minimum window 900x600. Hit target at least 24.
Copy: Theme names `Dark` and `Light` appear in E1-T09's settings UI, not as raw hex.
Accessibility: every icon-only control has an accessible name equal to its tooltip. Contrast uses the token ratios.

## Evidence required in the PR
Screenshots: dark and light, 100% and 150% scale. A short GIF when the interaction is more than a click. If the change runs on a keystroke, record that the JavaFX thread work stayed inside the 16 ms p95 budget in `docs/benchmarks/keystroke-latency.md` or say why this change does not run on a keystroke.
