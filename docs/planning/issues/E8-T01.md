# E8-T01 Audit keyboard access and contrast

Labels: `agent-task`, `epic:polish`, `size:M`, `kind:ui`

## Context
UI spec accessibility lines. TOKENS.md ratios.

## Goal
The main surfaces are usable without a pointer.

## Scope
Tab order matches the UI spec. Escape closes palette, quick open, and menus. Focus returns to the editor. Fix any control whose accessible name is empty.

## Out of scope
No new features.

## Design
A test walks the activity bar with the keyboard and records accessible text. Contrast is checked by reusing the token values, not by a screenshot parser.

## Implementation steps
1. Focus order test.
2. Fix empty names found by the test.
3. Note in the PR.

## Acceptance criteria
- Given focus on the editor, when Ctrl+Shift+P runs and Escape is pressed, then focus is back in the editor.
- Given each activity button, when its accessible text is read, then it is non-empty.

## Tests
FocusOrderTest.

## Verification
mvn -B -ntp -pl ccmm-app -am test

## Depends on
E1-T08, E3-T02.

## Blocks
None.

## Risks and fallbacks
Do not weaken tokens to make a control pretty.

## UX spec
Wireframe: docs/design/wireframes/workbench.md and docs/design/UI_SPEC.md.
Tokens only. Minimum window 900x600. Hit target at least 24.
Copy: No new copy except accessible names that were missing. Use the existing tooltips.
Accessibility: icon-only controls use the tooltip as the accessible name. Ctrl shortcuts are Cmd on macOS.

## Evidence required in the PR
Screenshots: dark and light, 100% and 150% scale. A short GIF when the interaction is more than a click. If the change runs on a keystroke, record that the JavaFX thread work stayed inside the 16 ms p95 budget in `docs/benchmarks/keystroke-latency.md` or say why this change does not run on a keystroke.
