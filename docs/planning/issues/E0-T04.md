# E0-T04 Measure theme tokens at high DPI

Labels: `agent-task`, `epic:spikes`, `size:M`, `kind:spike`

## Context
ADR-0013 recommends stylesheets from docs/design/TOKENS.md. Current AtlantaFX needs Java 25 and JavaFX 27, which ADR-0012 does not adopt.

## Goal
Show the dark and light token stylesheets at 100, 150, and 200 percent.

## Scope
Two stylesheets in the spike that use the token names. Screenshots at three scales on Windows.

## Out of scope
No AtlantaFX dependency in ccmm-app. No CI change.

## Question
Do the token values stay readable at 150% and 200%?

## Method
A spike scene shows text-primary, text-secondary, success, warn, danger, and one remote chip on surface-0 for both themes. Capture at 100, 150, and 200 percent. Note any clipped row at the 24 px tree height.

## Metrics
docs/benchmarks/hidpi.md plus the screenshots stored beside it.

## Go / no-go
Go when primary and secondary text match the ratios in TOKENS.md and rows are not clipped. A no-go lists the token to change. It does not add AtlantaFX.

## Output
Benchmark note. Token edits in TOKENS.md only if a value fails, with the new ratio computed the same way.

## Design
Stylesheets reference looked-up colours -fx-ccmm-text-primary and the other token names. No hex in the scene graph code.

## Implementation steps
1. Build the spike scene from the token file.
2. Capture three scales, both themes.
3. Write the note.

## Acceptance criteria
- Given the dark theme at 150%, when the scene is shown, then primary text is not clipped and the screenshot is in the benchmark folder.
- The note ends with go or names the token that failed.

## Tests
No product test.

## Verification
docs/benchmarks/hidpi.md

## Depends on
None.

## Blocks
E1-T08 if the note is a no-go, until the tokens are corrected.

## Risks and fallbacks
Windows scaling may differ from macOS. Record the OS. A macOS pass is E8-T02, not this spike.
