# E9-T02 Check for an update

Labels: `agent-task`, `epic:release`, `size:M`, `kind:code`

## Context
Release flow in AGENTS.md. Ask-first applies to release workflow changes. This issue is client-only.

## Goal
The IDE reports when the GitHub release is newer than the running version.

## Scope
Once a day, GET the public releases API for this repository off the FX thread. Compare to the package version. Status `Update <version> is available` is a link the user can copy. No download and no install.

## Out of scope
No auto-update. No change to release-please. No token.

## Design
Failure is silent except a debug log line. Offline does not change the status bar. The URL is the public GitHub API for the repo owner already in the remote. Tests use a fake HTTP response.

## Implementation steps
1. Version compare.
2. Client with a fake.
3. Status slot.

## Acceptance criteria
- Given a remote version greater than the local one, when the check finishes, then the bar reads `Update <version> is available`.
- Given a network error, when the check finishes, then the bar is unchanged.

UpdateCheckTest.

mvn -B -ntp -pl ccmm-app -am test

## Risks and fallbacks
