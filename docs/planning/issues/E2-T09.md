# E2-T09 Add large-file mode

Labels: `agent-task`, `epic:editor`, `size:M`, `kind:code`

## Context
ccmm-core already skips files over 1 MiB in scan. The editor has no such guard. ADR-0008 measures 5 MB.

## Goal
Large files stay editable and skip the expensive services.

## Scope
Threshold 1 MiB. Banner `Large file — highlighting is off`. No HighlightScheduler, no AnalysisScheduler. Editing still works. Metrics status shows nothing, not stale.

## Out of scope
No virtualization rewrite. That is the bake-off's problem if memory exceeds 500 MB.

## Design
The check uses file size before read when known, and string length after. A paste that grows a small file over the threshold enables the mode and cancels running jobs.

## Implementation steps
1. Flag on Document.
2. Banner and scheduler guards.
3. Test a file just over the threshold.

## Acceptance criteria
- Given a 1 MiB plus one byte file, when it opens, then the banner is shown and Analyzer.analyze is not called.
- Given typing in that file, when 300 ms passes, then no analysis result is published.

## Tests
LargeFileModeTest.

## Verification
mvn -B -ntp -pl ccmm-app -am test

## Depends on
E2-T01.

## Blocks
None.

## Risks and fallbacks
If E0-T01 shows the widget cannot hold 5 MB under 500 MB, this issue still ships the banner; the widget change is the bake-off's no-go plan.
