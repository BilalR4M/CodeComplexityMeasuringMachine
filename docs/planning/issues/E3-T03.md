# E3-T03 Search the project

Labels: `agent-task`, `epic:navigation`, `size:L`, `kind:ui`

## Context
UI spec Search. Ignore rules from E4-T01.

## Goal
The user can search text across the project.

## Scope
Side bar fields Search, Include, Exclude. Exclude defaults to the ignore rules. Results grouped by file. Cap 2,000 hits with `Showing 2,000 matches. Narrow the query.` Enter opens the file at the line via E2-T05's command.

## Out of scope
Replace across files can ship in this issue only if it stays inside size L; otherwise stop after search and file a follow-up. Prefer search only.

## Design
Worker thread `ccmm-search`, latest-wins. Do not read ignored directories.
Binary detection: a NUL in the first 8 KiB skips the file.
Empty query shows `Type to search in <folder>` and does not scan.
IOException on one file skips it and continues.

## Implementation steps
1. Scanner.
2. Result tree.
3. Open at line.

## Acceptance criteria
- Given an ignored directory containing the query, when search runs, then that file is not a hit and was not read.
- Given 2,001 hits, when the list renders, then it shows 2,000 and the narrow-query sentence.
- Given a hit, when it is activated, then the caret is on that line.

## Tests
ProjectSearchTest with a temp tree.

## Verification
mvn -B -ntp -pl ccmm-app -am test

## Depends on
E1-T02, E4-T01.

## Blocks
None.

## Risks and fallbacks
Searching node_modules would repeat the 3.2 s failure mode. The ignore check is the acceptance test.

## UX spec
Wireframe: docs/design/wireframes/search.md and docs/design/UI_SPEC.md.
Tokens only. Min 900x600.
Copy: `Search`, `Type to search in <folder>`, `Searching…`, `Nothing found`, `Showing 2,000 matches. Narrow the query.`.
Accessibility: field placeholders are also accessible names. Ctrl bindings are Cmd on macOS.
