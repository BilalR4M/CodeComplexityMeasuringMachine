# E4-T02 Load the tree lazily

Labels: `agent-task`, `epic:project`, `size:L`, `kind:ui`

## Context
FileNode.tree is eager. The heliogrid measurement is the baseline to beat for first paint, not a number to copy.

## Goal
The tree lists a directory only when it is expanded.

## Scope
FileNode.children becomes a one-level list. TreeItem expansion triggers list on ccmm-file-tree. A placeholder child makes the disclosure node appear.

## Out of scope
No file watcher (E4-T07).

## Design
list(Path) returns one level, directories first, then files, by name.
IOException: keep the folder and add a child whose name is `Could not read this folder`.
First root callback runs after the top level only.
Benchmark fixture: 100 top-level files plus one ignored directory of 30,000 files. Time to first root under 300 ms. The ignored directory is not opened.

## Implementation steps
1. One-level list.
2. Expansion listener.
3. Benchmark note.

## Acceptance criteria
- Given a collapsed directory, when the root is shown, then that directory's children are not FileNodes yet.
- Given expansion, when listing runs, then it is not on the JavaFX thread.
- The benchmark file records the fixture time and whether it is under 300 ms.

## Tests
FileNodeTest updated. LazyTreeTest.

## Verification
mvn -B -ntp -pl ccmm-app -am test

## Depends on
E4-T01.

## Blocks
None.

## Risks and fallbacks
A directory with 10,000 files in one level can still hitch on expand. Cap is not required; record it if seen. Do not load them at startup.

## UX spec
Wireframe: docs/design/wireframes/explorer.md and docs/design/UI_SPEC.md.
Tokens only. Min 900x600.
Copy: `Loading…`, `Could not read this folder`, `No folder opened`, `Open Folder…`.
Accessibility: field placeholders are also accessible names. Ctrl bindings are Cmd on macOS.
