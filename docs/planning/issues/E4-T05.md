# E4-T05 Create, rename, delete, and move files

Labels: `agent-task`, `epic:project`, `size:L`, `kind:ui`

## Context
Design brief project section. Path rules already exist for peers; local operations get the same containment check.

## Goal
The user can create, rename, delete, and move a file or folder inside the project.

## Scope
Commands and context menu entries. Create file, create folder, rename, delete, move via a target folder picked in the tree. All off the FX thread, tree refresh on the FX thread.

## Out of scope
No drag and drop. No undo of delete.

## Design
Reject absolute paths, `..`, and a target whose real path leaves the root.
Delete of a dirty document asks `Save changes to <name>?` first; Cancel aborts the delete.
Delete of a folder asks `Delete <name> and its contents?` with Delete and Cancel.
Name collision: status `A file named <name> already exists` and no overwrite.
IOException: status `Could not change <name>`.

## Implementation steps
1. FileOps with the containment check.
2. Commands.
3. Tests on a temp tree including a symlink that leaves the root.

## Acceptance criteria
- Given a rename to `../outside`, when it is attempted, then the file stays and the status explains the rejection.
- Given a new file `N.java`, when it is created, then it appears in the parent listing.
- Given delete of a dirty open file and Cancel, when the prompt closes, then the file remains.

## UX spec

Tokens only. Min 900x600.
Copy: `New File`, `New Folder`, `Rename`, `Delete`, `Move`, `Delete <name> and its contents?`, `A file named <name> already exists`, `Could not change <name>`.
Accessibility: field placeholders are also accessible names. Ctrl bindings are Cmd on macOS.
