# E4-T07 Refresh when files change

Labels: `agent-task`, `epic:project`, `size:M`, `kind:code`

## Context
Design brief: watcher, poll fallback on macOS.

## Goal
The tree updates when the disk changes.

## Scope
WatchService on the expanded directories. On macOS, if registration throws, poll every 2 s. Coalesce events for 200 ms. Ignore events inside ignored directories.

## Out of scope
No reload of a dirty buffer from disk. If the open file changes on disk and is dirty, status `File changed on disk` with no automatic overwrite.

## Design
Watcher thread `ccmm-watch`, daemon. FX thread applies tree updates. Closing the project closes the watch.

## Implementation steps
1. Watcher.
2. macOS fallback flag tested with a fake service.
3. Dirty-buffer warning.

## Acceptance criteria
- Given a new file in an expanded folder, when the event arrives, then the row appears.
- Given a dirty open file changed on disk, when the event arrives, then the buffer is unchanged and the status is `File changed on disk`.

## Tests
FileWatchTest using a manual event, not a sleep on the real disk, plus one disk test with a timeout.

## Verification
mvn -B -ntp -pl ccmm-app -am test

## Depends on
E4-T02.

## Blocks
E3-T01's live index refresh.

## Risks and fallbacks
Watching all of node_modules is the bug E4-T01 prevents. Do not register ignored dirs.
