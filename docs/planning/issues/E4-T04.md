# E4-T04 Decorate git status

Labels: `agent-task`, `epic:project`, `size:M`, `kind:ui`

## Context
UI spec explorer git colours. Status bar left slot.

## Goal
The tree and the status bar show git state.

## Scope
Run `git status --porcelain` and `git rev-parse --abbrev-ref HEAD` off the FX thread. Map paths to added (success), modified (warn), conflict (danger). Ignored files are absent, not dimmed.

## Out of scope
No commit, push, or diff viewer. Pre-flight gate is E5-T07.

## Design
Refresh on folder open and every 2 s while the window is focused, latest-wins. A missing git sets the branch slot to `no git` and clears colours. Do not start a git process on the FX thread. Timeout 5 s then keep the previous colours.

## Implementation steps
1. Parser of porcelain v1.
2. Apply colours.
3. Branch label.

## Acceptance criteria
- Given porcelain ` M src/A.java`, when it is applied, then that row uses the warn token.
- Given no .git, when the folder opens, then the status bar reads `no git`.

## Tests
GitStatusParserTest with sample porcelain, no real git required. One test may skip if git is absent for the process runner.

## Verification
mvn -B -ntp -pl ccmm-app -am test

## Depends on
E4-T02, E1-T05.

## Blocks
E5-T07.

## Risks and fallbacks
Windows paths in porcelain use '/'. Normalize.

## UX spec
Wireframe: docs/design/wireframes/explorer.md and docs/design/UI_SPEC.md.
Tokens only. Min 900x600.
Copy: Status bar `no git` or the branch name. No extra tooltips required.
Accessibility: field placeholders are also accessible names. Ctrl bindings are Cmd on macOS.
