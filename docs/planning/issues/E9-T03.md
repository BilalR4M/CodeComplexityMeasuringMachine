# E9-T03 Record the crash and log location

Labels: `agent-task`, `epic:release`, `size:S`, `kind:code`

## Context
Settings already use the OS config directory in E1-T09.

## Goal
Uncaught exceptions and the app log have a stable path.

## Scope
Log file `ccmm.log` beside settings, rotated at 1 MiB, two files kept. An uncaught FX exception writes one line and sets the status `Something went wrong. The log is in <path>`. Document the three OS paths.

## Out of scope
No crash upload. No workflow change.

## Design
The handler must not throw. Writing the log is synchronized. The status path is the absolute log path.

## Implementation steps
1. Log file.
2. Handler.
3. Doc section.

## Acceptance criteria
- Given an uncaught exception on the FX thread, when the handler runs, then the log file contains the exception class name and the status names the path.
- Given a log over 1 MiB, when the next line is written, then a new file starts and one backup remains.

## Tests
CrashLogTest.

## Verification
mvn -B -ntp -pl ccmm-app -am test

## Depends on
E1-T09.

## Blocks
None.

## Risks and fallbacks
Do not log invite tokens or file contents. Log the exception and the command id only.
