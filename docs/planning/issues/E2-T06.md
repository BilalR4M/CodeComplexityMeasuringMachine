# E2-T06 Match brackets

Labels: `agent-task`, `epic:editor`, `size:M`, `kind:ui`

## Context
Editor core in the design brief. Not a metric.

## Goal
The caret's bracket highlights its match.

## Scope
Pairs () [] {}. Highlight both when the caret is next to one. No match leaves the highlight clear.

## Out of scope
No rainbow indent guides. No auto-insert of the closing bracket (that is E2-T07 if it fits; this issue does not insert characters).

## Design
Scan on the FX thread only for a window of 5,000 characters around the caret. Beyond that, schedule the scan off-thread. Strings and comments are skipped with a tiny state machine, not the full highlighter. Mismatch does not show an error dialog.

## Implementation steps
1. Matcher.
2. Caret listener.
3. Tests including a string that contains a bracket.

## Acceptance criteria
- Given `if (ok) { }`, when the caret is on the opening paren, then the closing paren is marked.
- Given a bracket inside a string, when the caret is there, then it does not match a code bracket.

## Tests
BracketMatchTest.

## Verification
mvn -B -ntp -pl ccmm-app -am test

## Depends on
E2-T01.

## Blocks
None.

## Risks and fallbacks
A naive scan of a 5 MB file on the FX thread will miss the budget. The 5,000-character window is the guard.

## UX spec
Wireframe: docs/design/wireframes/editor.md. Section in docs/design/UI_SPEC.md.
Visuals: tokens only. 900x600 minimum.
Copy: No copy. The match uses the selection token at 50 percent, not a new colour.
Accessibility: icon buttons expose the tooltip as the accessible name. Keyboard shortcuts use Ctrl, and Cmd on macOS via the keymap.
