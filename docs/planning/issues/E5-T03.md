# E5-T03 Add the inspector

Labels: `agent-task`, `epic:metrics`, `size:L`, `kind:ui`

## Context
UI spec Inspector. MetricsPanel stays the data source until this view replaces it. Remove the Project / Here placeholder from the right rail.

## Goal
The right rail shows the method at the caret.

## Scope
Method name, CC, decision-point rows, MI, Halstead volume, nesting, rule line. Decision points are the AST nodes that add cyclomatic complexity, with line numbers. Click uses go.line.

## Out of scope
Git history sparkline is a follow-up if this issue would pass size L. The History heading reads `History is not available yet` in this issue.

## Design
Reuse Analyzer output. If MethodMetrics has no decision list, add an optional list on the core result in a small ccmm-core change: record DecisionPoint(String kind, int line). Kind is if, for, while, do, case, catch, and, or, ternary.
That core change is part of this issue and needs a golden-fixture update only if numbers change. They must not change.
Empty: `Click a complexity chip or a method in the outline`.
Outside a method: `Caret is outside a method`.
Never parsed: `This file has not parsed` plus the parser message.
Stale banner: `These numbers are stale`.

## Implementation steps
1. Extend the core result with decision points without changing metric numbers.
2. Inspector view.
3. Remove the placeholder ProjectRoomPanel title from the right rail. Chat moves in E7-T05; until then presence text can sit in the Collaboration view host from E1-T02.

## Acceptance criteria
- Given a method with one if, when the inspector renders, then a row says if and the line, and clicking it moves the caret.
- Given a parse failure after success, when the view renders, then the banner is `These numbers are stale` and the numbers remain.
- Given golden fixtures, when tests run, then cyclomatic numbers are unchanged.
