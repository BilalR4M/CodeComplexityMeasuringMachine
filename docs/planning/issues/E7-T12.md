# E7-T12 Reconnect without dropping local edits

Labels: `agent-task`, `epic:collaboration`, `size:M`, `kind:code`

## Context
COLLABORATION.md reconnect rules.

## Goal
The client reconnects and keeps the local buffer.

## Scope
On socket close, status `Reconnecting…` and `<n> edits buffered`. Local typing continues. Buffered LOCAL ops flush in order after reconnect. If the server revision diverged, show the same mismatch prompt as E7-T02 instead of overwriting.

## Out of scope
No silent discard of the buffer.

## Design
Buffer cap 1,000 ops. Over the cap, stop sending, keep the buffer, and set status `Too many offline edits. Save your file.`

## Implementation steps
1. Buffer.
2. Reconnect with a fake socket.
3. Divergence prompt.

## Acceptance criteria
- Given three local inserts while the socket is down, when it returns, then those inserts are still in the document.
- Given the disconnect, when the view renders, then it reads `Reconnecting…`.

## Tests
ReconnectBufferTest.

## Verification
mvn -B -ntp -pl ccmm-app -am test

## Depends on
E7-T01, E2-T01.

## Blocks
None.

## Risks and fallbacks
Do not block the FX thread on reconnect sleeps. Backoff lives on ccmm-relay.
