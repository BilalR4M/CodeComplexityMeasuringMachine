# E7-T03 Draw remote carets

Labels: `agent-task`, `epic:collaboration`, `size:L`, `kind:ui`

## Context
docs/architecture.md RemoteCaret. TOKENS remote-1 through remote-8.

## Goal
Peers see each other's carets and selections.

## Scope
Presence gains an offset range for the active file, or a new selection message if presence cannot carry it. Colour index assigned in join order. Name flag uses the chip text token from TOKENS.md. Viewport does not move.

## Out of scope
No follow. That is E7-T04.

## Design
Selection messages are batched on the FX thread with text ops. A selection for another file is stored and not drawn. Colour is never the only signal: the flag includes the display name.

## Implementation steps
1. Message or presence field, with codec tests.
2. Decoration.
3. Assert the scroll position is unchanged.

## Acceptance criteria
- Given a peer selection, when it is applied, then the flag text is the display name and the scroll position is the same.
- Given peer nine, when they join, then they reuse the lowest free colour index.

## Tests
RemoteCaretTest.

## Verification
mvn -B -ntp -pl ccmm-app -am test

## Depends on
E2-T01, E0-T01, E7-T01.

## Blocks
E7-T04.

## Risks and fallbacks
If presence cannot grow a field without a protocol break, add a new message type and note it. Do not silently change join.

## UX spec
Wireframe: docs/design/wireframes/editor.md and docs/design/UI_SPEC.md.
Tokens only. Minimum window 900x600. Hit target at least 24.
Copy: Flag text is the display name. Tooltip ` <name> `.
Accessibility: icon-only controls use the tooltip as the accessible name. Ctrl shortcuts are Cmd on macOS.

## Evidence required in the PR
Screenshots: dark and light, 100% and 150% scale. A short GIF when the interaction is more than a click. If the change runs on a keystroke, record that the JavaFX thread work stayed inside the 16 ms p95 budget in `docs/benchmarks/keystroke-latency.md` or say why this change does not run on a keystroke.
