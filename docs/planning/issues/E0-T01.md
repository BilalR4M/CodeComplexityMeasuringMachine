# E0-T01 Compare editor components

Labels: `agent-task`, `epic:spikes`, `size:L`, `kind:spike`

## Context
ADR-0001 accepted RichTextFX. ADR-0008 is proposed and stays proposed until this spike. docs/benchmarks/keystroke-latency.md records p95 1.245 ms and 302.6 MB committed on a 10,000-line buffer.

## Goal
Decide whether RichTextFX stays the editor or a no-go names a replacement.

## Scope
A throwaway harness under spikes/e0-t01/. Two components: RichTextFX CodeArea on JavaFX 21, and the incubating JavaFX CodeArea on a newer JavaFX that is not applied to the parent POM.

## Out of scope
No change to ccmm-app sources, pom versions, or ADR-0001. No third toolkit that cannot sit in a JavaFX scene.

## Question
Which component hosts gutter chips and remote carets inside the budgets?

## Method
On this Windows workstation, load a 10,000-line Java buffer and a 5 MB text file into each component. Record keystroke p95 (200 inserts, same method as KeystrokeLatencyHarness), a scroll of the 5 MB file, committed memory after load, whether a side decoration can show a chip, whether the caret index can be set without scrolling, and whether folding is feasible. Note the JavaFX version used for the incubating control.

## Metrics
docs/benchmarks/editor-bakeoff.md: OS, JavaFX version, p95, committed memory, scroll note, decoration yes/no, folding yes/no, command line.

## Go / no-go
Go for RichTextFX when p95 is under 16 ms, committed memory on the 5 MB file is under 500 MB, a remote caret can be drawn without moving the viewport, and a gutter chip can be shown. Folding is recorded and is not required. A no-go names the replacement, says E2 tasks that assume RichTextFX stop, and does not implement the loser. Choosing the incubating control also requires ADR-0012 to be accepted later.

## Output
Update the consequences section of ADR-0008 with the measured result. Do not mark it accepted. Leave spike sources under spikes/e0-t01/.

## Design
Harness main classes stay in spikes/e0-t01/src. They must not be referenced from ccmm-app. Reuse the percentile function from KeystrokeReport rather than copying a new definition if the spike module can depend on test-classes; otherwise duplicate the rank function and say so in the benchmark file.

## Implementation steps
1. Add spikes/e0-t01 as a non-reactor module or a standalone Maven file that is not part of mvn verify.
2. Measure RichTextFX on the current toolchain.
3. Measure the incubating control on a side toolchain.
4. Write the benchmark file and the ADR note.

## Acceptance criteria
- Given the 10,000-line buffer, when 200 inserts are timed, then p95, memory, and the OS are in the benchmark file.
- Given the 5 MB file, when it is loaded, then committed memory and a scroll note are in the file.
- The file ends with go or no-go, and a no-go names the plan change.

## Tests
No product test. The benchmark file is the artifact. ccmm-app tests still pass.

## Verification
docs/benchmarks/editor-bakeoff.md contains both buffers and a decision. mvn -B -ntp -pl ccmm-app -am test

## Depends on
None.

## Blocks
E2-T03, E2-T10, E5-T01, and E7-T03 until the decision is go or the plan is updated.

## Risks and fallbacks
The incubating API may not run on JDK 21. Record that and leave RichTextFX as the go if it meets the thresholds.
