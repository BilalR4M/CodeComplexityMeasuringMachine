# E1-T09 Add a settings store

Labels: `agent-task`, `epic:workbench`, `size:M`, `kind:code`

## Context
UI spec Settings. ADR-0013 theme names.

## Goal
Settings persist in the per-OS user config directory.

## Scope
SettingsStore load/save. Keys: theme (dark|light), editorFontSize (8..32), ligatures (off|on), relayUrl, displayName. Path: Windows %APPDATA%/ccmm/settings.properties, macOS ~/Library/Application Support/ccmm/settings.properties, other ~/.config/ccmm/settings.properties.

## Out of scope
No settings screen polish beyond the fields in the UI spec. That view is this issue's UI because the store is useless without it. Keep it inside the L budget.

## Design
Invalid relay URL does not save. Status under the field: `Enter a ws:// or wss:// URL`.
Font size outside 8..32 does not save.
Missing file loads defaults: dark, 13, ligatures off, relay empty, display name the OS user name.
Reset asks `Reset all settings?` with Reset and Cancel.
Write to a temp file then move, so a crash does not empty the file.

## Implementation steps
1. Store and path selection.
2. Settings view bound to the store.
3. Tests with a temp directory, not the real APPDATA.

## Acceptance criteria
- Given a saved theme light, when the store loads, then theme is light.
- Given relay URL http://example, when save is attempted, then the previous URL remains and the field shows `Enter a ws:// or wss:// URL`.
- Given Reset confirmed, when it finishes, then defaults are on disk.

## Tests
SettingsStoreTest.

## Verification
mvn -B -ntp -pl ccmm-app -am test

## Depends on
E1-T06. Theme application also needs E1-T08; this issue may store the value before the stylesheet exists.

## Blocks
E1-T10, E7-T01's relay URL.

## Risks and fallbacks
Do not write secrets. The relay URL is not a token. The invite token is not stored in this file.
