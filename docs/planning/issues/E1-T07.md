# E1-T07 Add a keymap

Labels: `agent-task`, `epic:workbench`, `size:M`, `kind:code`

## Context
UI spec shortcut rule. Temporary handlers from E1-T02 move here.

## Goal
Key bindings resolve to command ids.

## Scope
Keymap with bind(shortcut, commandId). Platform detection uses os.name starting with Mac. Seed bindings from the UI spec: Ctrl+B, Ctrl+J, Ctrl+Alt+B, Ctrl+Shift+E, Ctrl+Shift+F, Ctrl+Shift+O, Ctrl+P, Ctrl+Shift+P, Ctrl+F, Ctrl+H, Ctrl+G, Ctrl+W, Ctrl+Shift+T, Ctrl+,.

## Out of scope
Commands that do not exist yet no-op with status `Command is not available yet`. Do not implement find or quick open here.

## Design
Shortcut is key combination plus modifiers. A binding for a missing command id is allowed and reports the status string. Tests use a fake platform flag, not the real OS only.

## Implementation steps
1. Add Keymap.
2. Remove the temporary handlers from E1-T02.
3. Test Mac versus other.

## Acceptance criteria
- Given a Mac platform flag, when Cmd+P is pressed, then command quick.open is invoked.
- Given Windows, when Ctrl+P is pressed, then the same command id is invoked.
- Given a missing command, when the binding fires, then the status bar reads `Command is not available yet`.

## Tests
KeymapTest.

## Verification
mvn -B -ntp -pl ccmm-app -am test

## Depends on
E1-T06.

## Blocks
None. Later issues register their command ids.

## Risks and fallbacks
JavaFX KeyCharacter combinations differ by OS. Test the mapping table, and one focused scene test for Ctrl+B.
