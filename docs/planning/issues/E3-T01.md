# E3-T01 Open files by name

Labels: `agent-task`, `epic:navigation`, `size:L`, `kind:ui`

## Context
UI spec Quick open. REFERENCE_SURVEY Sublime decision. Assessment tree timing.

## Goal
Ctrl+P opens a file by a substring of its path.

## Scope
An index of project-relative paths built off the FX thread, using E4-T01 ignore rules. Popup with placeholder `Search files by name`. At most 50 rows. Enter pins the file. Escape returns focus to the editor.

## Out of scope
No symbol search. Java symbols in the outline are E3-T04.

## Design
Index rebuilds when the watcher (E4-T07) says the tree changed; until that issue lands, rebuild on folder open and on a manual command `Refresh File Index`.
Ignored directories are not listed. The first paint of the popup does not wait for the full index: show `Indexing…` and accept typing.
Ranking is case-insensitive substring, path segments preferred over mid-name matches. State the comparator in the test.

## Implementation steps
1. Indexer.
2. Popup.
3. Benchmark fixture with an ignored directory that must not be walked.

## Acceptance criteria
- Given node_modules is ignored, when the index builds, then no path under it appears and the benchmark says the directory was not listed.
- Given a query with no match, when the list renders, then it reads `No matching files`.
- Given Enter on a row, when it runs, then that file is a pinned tab.

## Tests
QuickOpenTest, QuickOpenIndexTest.

## Verification
mvn -B -ntp -pl ccmm-app -am test

## Depends on
E1-T07, E4-T01, E2-T02.

## Blocks
None.

## Risks and fallbacks
A slow index must not freeze the popup. Latest-wins if the folder changes mid-build.

## UX spec
Wireframe: docs/design/wireframes/quick-open.md and docs/design/UI_SPEC.md.
Tokens only. Min 900x600.
Copy: `Search files by name`, `Indexing…`, `No matching files`, `No recent files`.
Accessibility: field placeholders are also accessible names. Ctrl bindings are Cmd on macOS.
