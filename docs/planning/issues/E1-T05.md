# E1-T05 Add the status bar shell

Labels: `agent-task`, `epic:workbench`, `size:M`, `kind:ui`

## Context
UI spec status bar. Metrics numbers land in E5-T04. Git branch lands in E4-T04.

## Goal
A status bar shows caret position and a slot for later items.

## Scope
Left slot and right slot. Right slot shows `Ln <n>, Col <n>` from the CodeArea. Left slot shows `no git` until E4-T04.

## Out of scope
No CC or MI yet. No collaboration count.

## Design
StatusBar height 24. Caret listener reads paragraph and column on the FX thread only. Text uses text-secondary. Error string `Could not open folder` replaces the left slot until the next successful open.

## Implementation steps
1. Add the bar.
2. Bind the caret.
3. Surface the existing failed-open path.

## Acceptance criteria
- Given a buffer with the caret on line 3 column 2, when the caret moves there, then the bar reads `Ln 3, Col 2`.
- Given a missing directory, when open is called, then the bar reads `Could not open folder`.

## Tests
StatusBarTest.

## Depends on
E1-T01.

## Blocks
E5-T04, E4-T04's branch slot, E2-T08.

## Risks and fallbacks
Caret events are frequent. Read positions only; do not analyze.

## UX spec
Wireframe: docs/design/wireframes/status-bar.md and the matching section of docs/design/UI_SPEC.md.
States: empty, populated, error.
Visuals: token names from docs/design/TOKENS.md only. Minimum window 900x600. Hit target at least 24.
Copy: `Ln 1, Col 1` when the editor is empty. `Could not open folder`.
Accessibility: every icon-only control has an accessible name equal to its tooltip. Contrast uses the token ratios.
