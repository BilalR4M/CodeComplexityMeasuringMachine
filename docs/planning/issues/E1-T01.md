# E1-T01 Add workbench regions

Labels: `agent-task`, `epic:workbench`, `size:L`, `kind:ui`

## Context
docs/architecture.md Workbench section. docs/design/UI_SPEC.md Workbench shell. IdeWindow is the current BorderPane.

## Goal
The window has an activity bar, side bar, editor, inspector, bottom panel, and status bar.

## Scope
Region containers and sash resizing. Existing tree, editor, and metrics labels move into the side bar and inspector without new behaviour.

## Out of scope
No commands, themes, or new metrics. Do not delete AnalysisScheduler.

## Design
Package dev.bilal.ccmm.app.workbench. Workbench holds RegionId and show(RegionId, boolean).
The root is a BorderPane: top menu, bottom status, center a split of side | editor | inspector, with the bottom panel under the editor.
Default widths: activity 48, side 260, inspector 280, bottom 180. Minimums: side 160, inspector 200, bottom 80.
Double-click a sash collapses that region. Below 1100 px the inspector starts collapsed.
FX thread only. Moving the existing TreeView and CodeArea is a reparent, not a rewrite.
Errors: a failed directory open leaves the previous project and sets the status text to "Could not open folder".

## Implementation steps
1. Introduce Workbench and reparent the current controls.
2. Add sashes and the width rules.
3. Keep IdeWindowTest assertions true, updating only the lookup path.

## Acceptance criteria
- Given a 1280x800 window, when a folder is open, then the editor column is at least 65 percent of the width.
- Given a width under 1100, when the window opens, then the inspector is collapsed.
- Given the current open-directory action, when it runs, then the tree still lists files.

## Tests
WorkbenchLayoutTest beside IdeWindowTest. Skip only while ADR-0015 is open; once the harness exists, do not skip.

## Verification
mvn -B -ntp -pl ccmm-app -am test

## Depends on
None.

## Blocks
E1-T02 through E1-T05.

## Risks and fallbacks
Reparenting can break IdeWindowTest lookups. Update the test rather than weakening it.

## UX spec
Wireframe: docs/design/wireframes/workbench.md and the matching section of docs/design/UI_SPEC.md.
States: empty, loading, populated, error.
Visuals: token names from docs/design/TOKENS.md only. Minimum window 900x600. Hit target at least 24.
Copy: Window title `CCMM IDE — <folder>` or `CCMM IDE`. Status `Opening…` while the tree loads.
Accessibility: every icon-only control has an accessible name equal to its tooltip. Contrast uses the token ratios.

Screenshots: dark and light, 100% and 150% scale. A short GIF when the interaction is more than a click. If the change runs on a keystroke, record that the JavaFX thread work stayed inside the 16 ms p95 budget in `docs/benchmarks/keystroke-latency.md` or say why this change does not run on a keystroke.
