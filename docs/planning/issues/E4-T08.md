# E4-T08 Add explorer context menus

Labels: `agent-task`, `epic:project`, `size:M`, `kind:ui`

## Context
UI spec explorer. Commands already exist.

## Goal
A context menu runs the file commands.

## Scope
Menu: New File, New Folder, Rename, Delete, Move, Reveal in File Manager, Copy Path, Copy Relative Path. Copy Path copies the absolute path to the clipboard. Copy Relative Path copies the '/' path.

## Out of scope
No extra commands.

## Design
The menu is built from the same command ids. A directory and a file show the same set. Keyboard Shift+F10 opens it when the tree is focused.

## Implementation steps
1. Menu.
2. Clipboard commands.
3. Test the items exist.

## Acceptance criteria
- Given a selected file, when the context menu opens, then `Copy Relative Path` is present.
- Given Copy Relative Path, when it runs, then the clipboard text uses '/'.

## Tests
ExplorerMenuTest.

## Verification
mvn -B -ntp -pl ccmm-app -am test

## Depends on
E4-T05, E4-T06.

## Blocks
None.

## Risks and fallbacks
Clipboard access can throw on a headless runner. Catch it and set the status. Do not fail the test suite for a missing clipboard if ADR-0015's harness has no clipboard; assert the string the command would copy.

## UX spec
Wireframe: docs/design/wireframes/explorer.md and docs/design/UI_SPEC.md.
Tokens only. Min 900x600.
Copy: `New File`, `New Folder`, `Rename`, `Delete`, `Move`, `Reveal in File Manager`, `Copy Path`, `Copy Relative Path`.
Accessibility: field placeholders are also accessible names. Ctrl bindings are Cmd on macOS.

## Evidence required in the PR
Screenshots: dark and light, 100% and 150% scale. A short GIF when the interaction is more than a click. If the change runs on a keystroke, record that the JavaFX thread work stayed inside the 16 ms p95 budget in `docs/benchmarks/keystroke-latency.md` or say why this change does not run on a keystroke.
