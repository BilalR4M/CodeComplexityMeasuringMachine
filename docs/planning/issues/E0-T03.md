# E0-T03 Prove anchors survive operational transform

Labels: `agent-task`, `epic:spikes`, `size:M`, `kind:spike`

## Context
ADR-0002 is accepted. ADR-0011 recommends transforming a ThreadAnchor with the same ops. P0-T02 already converges plain text.

## Goal
Show that an anchor range still covers the same characters after concurrent edits above it.

## Scope
Protocol tests only. An anchor is a start offset and an end offset in code units.

## Out of scope
No JavaFX. No relay process. No comment text storage.

## Question
Does the existing OT keep an anchor attached when both clients insert and delete above it?

## Method
Extend the P0-T02 convergence cases. Each client also holds an anchor. Apply the server-ordered ops to the anchor the same way as to the text. Include an insert inside the range, a delete that shortens it, and a delete that removes it.

## Metrics
docs/benchmarks/anchor-ot.md ends with go or no-go. Tests are the proof.

## Go / no-go
Go when both clients finish on the same string and the same anchor offsets, and a fully deleted range is reported as removed rather than as a negative span. A no-go blocks E7-T07 and says ADR-0002 is not sufficient for anchors; it does not introduce a CRDT.

## Output
Benchmark note plus tests in ccmm-collab-protocol. ADR-0011 consequences get one sentence. Status stays proposed.

## Design
Add AnchorTransformer.next(start, end, op) beside the existing text transform. Inserts before the range shift both ends. Inserts inside grow the end. Deletes follow the same cases. A range that collapses to empty is removed.

## Implementation steps
1. Write the failing tests.
2. Implement the transformer using the existing op types.
3. Record go or no-go.

## Acceptance criteria
- Given an anchor on characters 10..20, when both clients insert 5 characters at 0, then both anchors are 15..25.
- Given a delete that covers the anchor, when it is applied, then the anchor is removed.
- Both clients still converge on the text.

## Tests
AnchorTransformTest in ccmm-collab-protocol.

## Verification
mvn -B -ntp -pl ccmm-collab-protocol test

## Depends on
None.

## Blocks
E7-T07.

## Risks and fallbacks
If the current op model cannot express the transform, stop with Decision needed rather than changing the wire format in this spike.
