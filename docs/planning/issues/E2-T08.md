# E2-T08 Show encoding and line endings

Labels: `agent-task`, `epic:editor`, `size:M`, `kind:ui`

## Context
UI spec status bar. Files are read with Files.readString today, which is UTF-8.

## Goal
The user can see and switch line endings, and see the encoding.

## Scope
Detect CRLF if any CRLF pair exists, otherwise LF. Status text `LF` or `CRLF`, and `UTF-8`. A click menu sets the ending for the next save. Invalid UTF-8: open as Latin-1 replacement is forbidden; show `Could not read <name> as UTF-8` and do not replace the buffer.

## Out of scope
No encoding conversion beyond rejecting non-UTF-8. No UTF-16.

## Design
Save writes the chosen ending and UTF-8. Switching ending marks dirty. Detection does not mark dirty.

## Implementation steps
1. Detect on load.
2. Status items.
3. Save uses the choice.

## Acceptance criteria
- Given a file with CRLF, when it opens, then the status bar shows `CRLF` and `UTF-8`.
- Given a switch to LF, when the file is saved, then the bytes contain `\n` and no `\r`.
- Given a byte 0xFF, when open is attempted, then the status reads `Could not read <name> as UTF-8` and the previous document stays.

## Depends on

## Risks and fallbacks
Files.readString throws on bad UTF-8. Catch it off the FX thread in the existing reader.
