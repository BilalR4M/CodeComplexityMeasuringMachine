# E2-T10 Fold regions the bake-off allows

Labels: `agent-task`, `epic:editor`, `size:L`, `kind:ui`

## Context
ADR-0008 says folding is recorded and not required for a go. This issue implements it only when the benchmark says yes.

## Goal
The user can fold a brace block.

## Scope
Gutter fold markers for `{` `}` regions in the open buffer. Click toggles. The caret moving into a folded region expands it.

## Out of scope
If editor-bakeoff.md says folding is not feasible, do not implement a fake. Close the issue as won't do and point at the file.

## Design
Fold state is local, not a remote op, and not persisted. Building the fold list runs off the FX thread. Applying it is one FX update.

## Implementation steps
1. Read the bake-off. Stop if folding is no.
2. Compute ranges.
3. Toggle.

## Acceptance criteria
- Given the bake-off says yes, when a method is folded, then its body is hidden and the signature line remains.
- Given the bake-off says no, when this issue is closed, then no fold control ships and the PR only cites the benchmark.

## Tests
FoldRangeTest for the range finder, widget test only if folding ships.

## Verification
mvn -B -ntp -pl ccmm-app -am test

## Depends on
E0-T01.

## Blocks
None.

## Risks and fallbacks
Do not miss the keystroke budget. Fold computation is not on the key handler.

## UX spec
Wireframe: docs/design/wireframes/editor.md. Section in docs/design/UI_SPEC.md.
Visuals: tokens only. 900x600 minimum.
Copy: Fold control accessible name `Fold` or `Expand`.
Accessibility: icon buttons expose the tooltip as the accessible name. Keyboard shortcuts use Ctrl, and Cmd on macOS via the keymap.

## Evidence required in the PR
Screenshots: dark and light, 100% and 150% scale. A short GIF when the interaction is more than a click. If the change runs on a keystroke, record that the JavaFX thread work stayed inside the 16 ms p95 budget in `docs/benchmarks/keystroke-latency.md` or say why this change does not run on a keystroke.
