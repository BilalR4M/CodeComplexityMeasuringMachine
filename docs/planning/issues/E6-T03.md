# E6-T03 Embed a terminal

Labels: `agent-task`, `epic:run`, `size:L`, `kind:ui`

## Context
COLLABORATION.md says a shared terminal is post-v1. This tab is local.

## Goal
The user can open a local shell in the project root.

## Scope
Bottom tab Terminal. Windows uses powershell.exe, others the user's SHELL or /bin/sh. The PTY library is ask-first: stop with Decision needed before adding a dependency. A pipe-based process is the fallback and must be named in the PR.

## Out of scope
No relay bytes. No guest input. No write access for a viewer.

## Design
If a dependency is required, do not add it. Comment Decision needed on the issue and stop. The fallback uses ProcessBuilder and a text area, with the limitation that full-screen programs will not work, stated in the tab: `Basic terminal — full-screen programs are not supported`.

## Implementation steps
1. Choose pipe fallback unless a dependency is already approved.
2. Tab.
3. Test that no collab message is created.

## Acceptance criteria
- Given the tab, when a local echo runs, then the text appears and ProjectRoom receives nothing.
- Given a viewer role from E7-T10, when the tab is focused, then input is disabled. Until roles exist, the tab is always local to this process.

## Tests
LocalTerminalTest with a fake process.

## Verification
mvn -B -ntp -pl ccmm-app -am test

## Depends on
E6-T02.

## Blocks
None.

## Risks and fallbacks
A real PTY dependency is ask-first. The fallback is the planned path.

## UX spec
Wireframe: docs/design/wireframes/workbench.md and docs/design/UI_SPEC.md.
Tokens only. Minimum window 900x600. Hit target at least 24.
Copy: `Terminal`, `Basic terminal — full-screen programs are not supported`.
Accessibility: icon-only controls use the tooltip as the accessible name. Ctrl shortcuts are Cmd on macOS.

## Evidence required in the PR
Screenshots: dark and light, 100% and 150% scale. A short GIF when the interaction is more than a click. If the change runs on a keystroke, record that the JavaFX thread work stayed inside the 16 ms p95 budget in `docs/benchmarks/keystroke-latency.md` or say why this change does not run on a keystroke.
