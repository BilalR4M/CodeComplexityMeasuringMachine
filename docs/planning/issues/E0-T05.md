# E0-T05 Prove headless UI tests on CI

Labels: `agent-task`, `epic:spikes`, `size:M`, `kind:spike`

## Context
ADR-0015 is proposed. ci.yml runs mvn verify on ubuntu, windows, and macos with no framebuffer.

## Goal
Find the smallest harness that executes IdeWindowTest instead of skipping it.

## Scope
A spike branch experiment. Prefer Xvfb on Linux. Try Monocle only if Xvfb cannot start JavaFX.

## Out of scope
No workflow edit in the spike PR if this issue is implemented before ADR-0015 is accepted. Stop with Decision needed in that case. The planning docs do not change CI.

## Question
Can the existing window test run on ubuntu-latest?

## Method
Run IdeWindowTest on the three OS. Record skip versus pass. If Linux skips, rerun under xvfb-run. If that fails, try Monocle in the spike only.

## Metrics
docs/benchmarks/ui-tests.md: OS, command, pass or skip, and the chosen harness.

## Go / no-go
Go when IdeWindowTest executes on all three OS. A no-go names the OS that still skips and blocks new UI tests that claim to be headless.

## Output
The note and, only after ADR-0015 is accepted, the workflow change as a follow-up issue if this spike's PR must stay docs-free. This issue's implementation PR may include the workflow only after acceptance.

## Design
Do not add TestFX until Monocle or Xvfb has failed. Document the exact apt package or JVM flag.

## Implementation steps
1. Confirm the skip on a headless run.
2. Retry with xvfb-run.
3. Write the note. Do not commit a workflow change unless ADR-0015 is accepted.

## Acceptance criteria
- Given a headless Linux JVM, when the chosen harness runs IdeWindowTest, then the test is not skipped.
- The note ends with go or no-go.

## Tests
The existing IdeWindowTest is the subject. No new product behaviour.

## Verification
docs/benchmarks/ui-tests.md

## Depends on
None.

## Blocks
E1 UI tests that would otherwise skip on Linux.

## Risks and fallbacks
CI edits are ask-first. If the owner has not accepted ADR-0015, the PR contains the note only.
