# E7-T06 Show presence on the tree and tabs

Labels: `agent-task`, `epic:collaboration`, `size:M`, `kind:ui`

## Context
COLLABORATION.md P1. The tree is still not synced. Dots are local decorations from presence messages.

## Goal
The tree and tabs show who is in each file.

## Scope
A dot using the peer colour token plus the accessible name `<name> is in this file`. Tab shows the same dot. Gutter badge `2 editing this method` when two peers' carets fall in one method.

## Out of scope
No file creation from presence.

## Design
Presence that names a path still passes P4-T02. A path outside the project is ignored. Unknown files do not appear as new tree nodes.

## Implementation steps
1. Map peer to path.
2. Dots.
3. Method badge.

## Acceptance criteria
- Given Ada in Foo.java, when presence arrives, then the Foo.java row exposes `Ada is in this file` and no new file is created.
- Given a path `../x`, when presence arrives, then no dot is shown.

## Tests
PresenceDecorationTest.

## Verification
mvn -B -ntp -pl ccmm-app -am test

## Depends on
E2-T02, E4-T02, E7-T03.

## Blocks
None.

## Risks and fallbacks
Do not treat presence as a file-tree sync.

## UX spec
Wireframe: docs/design/wireframes/explorer.md and docs/design/UI_SPEC.md.
Tokens only. Minimum window 900x600. Hit target at least 24.
Copy: `<name> is in this file`, `<n> editing this method`.
Accessibility: icon-only controls use the tooltip as the accessible name. Ctrl shortcuts are Cmd on macOS.
