# E7-T04 Follow a collaborator

Labels: `agent-task`, `epic:collaboration`, `size:L`, `kind:ui`

## Context
UI spec Follow chip. REFERENCE_SURVEY Zed and Live Share. COLLABORATION.md.

## Goal
Clicking a person follows their caret until the local user navigates.

## Scope
Click a session row. Chip `Following <name>` and `Stop`. File switches open that file. Local caret move, scroll, or file open stops follow and hides the chip. Remote edits do not stop it and do not scroll unless following.

## Out of scope
No forced follow on join. The host may send `follow me` as a request the guest accepts with the same click. No auto-accept.

## Design
One toast at most per join or leave burst: `<name> joined` or `<name> left`, and further names in the same 2 s collapse into `<n> people joined`.

## Implementation steps
1. Follow state.
2. Chip.
3. Stop conditions.
4. Toast coalesce.

## Acceptance criteria
- Given follow is on, when the peer changes file, then this client opens that file.
- Given follow is on, when the local user presses an arrow key, then the chip hides.
- Given three joins in one second, when the toasts render, then one toast is shown.

## Risks and fallbacks
Do not steal focus. Opening a file must not move window focus if the user is in another application. Stay inside the stage.

## UX spec
Wireframe: docs/design/wireframes/follow.md and docs/design/UI_SPEC.md.
Tokens only. Minimum window 900x600. Hit target at least 24.
Copy: `Following <name>`, `Stop`, tooltip `You are following <name>. Click Stop, or move the caret, to follow on your own.` Toast `<name> joined`, `<name> left`, `<n> people joined`.
Accessibility: icon-only controls use the tooltip as the accessible name. Ctrl shortcuts are Cmd on macOS.
